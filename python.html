A Small History of Python

Interestingly,the programming language was not actually named after the snake. Its creator, Guido van Rossum, named it after the British comedy programme Monty Python’s Flying Circus. He wanted a name that was short, memorable, and slightly playful.

Python was created by the Dutch programmer Guido van Rossum. He began developing it during the late 1980s while working at the Centre for Mathematics and Computer Science in the Netherlands. The first public version of Python was released in 1991. Guido wanted to create a programming language that was powerful but still easy to read. He believed that computer instructions should not look unnecessarily complicated. This focus on readability later became one of Python’s greatest strengths.

1.2 Types of Computer Languages

Computer languages have developed over time to make communication with computers easier. The closer a language is to the computer's hardware, the more difficult it is for humans to read. The closer it is to human language, the easier it is for people to write and understand.

Computer languages can be broadly divided into two main groups:

  1. Low-level languages
  2. High-level languages
Remember: “Low-level” does not mean unimportant or poor quality. It means that the language works close to the computer's hardware. Similarly, “high-level” means that the language is closer to human-readable ideas.

1.2.1 Low-Level Languages

A low-level language provides instructions that are very close to the computer's hardware. These languages give programmers more direct control over the processor and memory.

Low-level languages are usually more difficult for humans to read, write, debug, and maintain. They may also depend on the particular processor or computer architecture being used.

Low-level languages are divided into two main types:

  • Machine language
  • Assembly language

1.2.2 Machine-Level Language

Machine language, also called machine code, is the lowest-level computer language. It consists of instructions represented using binary digits: 0 and 1.

A machine-language instruction may look like this: 

10110000 01100001

To a beginner, this looks like a random collection of zeros and ones. However, to a particular processor, the sequence may represent an operation such as moving data, adding values, or comparing two values.

Machine language can be executed directly by the computer's processor. It does not need to be translated into another language before execution.

✓

Directly Executable

The processor can execute machine-language instructions directly.

✓

Fast and Hardware-Specific

The instructions are designed for a particular processor architecture.

!

Difficult to Read

Long sequences of zeros and ones are extremely difficult for humans to understand.

!

Difficult to Maintain

Finding and correcting mistakes in machine code is complicated and time-consuming.

Machine language is also processor dependent. Instructions written for one type of processor may not work on a different processor.

Simple analogy: Machine language is like communicating with a machine using its own native language. The computer understands it perfectly, but humans find it very difficult.

1.2.3 Assembly Language

Writing every instruction using zeros and ones is extremely difficult. Assembly language was developed to make low-level programming slightly easier.

Assembly language uses short symbolic instructions, called mnemonics, instead of binary sequences.

An assembly instruction may look like this: 

MOV AX, 5
ADD AX, 3

Here, words such as MOV and ADD are easier for a programmer to remember than binary instructions.

  • MOV may be used to move or store data.
  • ADD may be used to add values.
  • SUB may be used to subtract values.
  • JMP may be used to move to another instruction.

A computer processor cannot directly execute assembly-language instructions. A translator called an assembler converts assembly language into machine language.

Assembly-language process:
Assembly instructions → Assembler → Machine code → Processor

Assembly language is easier than machine language, but it is still closely connected to the computer's processor, registers, memory, and hardware. Therefore, it is also classified as a low-level language.

1.2.4 High-Level Languages

A high-level language is designed to make programming easier for humans. Its instructions use recognizable words, symbols, and structures instead of long sequences of binary digits.

Examples of high-level programming languages include:

  • Python
  • C
  • C++
  • Java
  • JavaScript
  • Fortran
  • R
  • MATLAB

Programs written in a high-level language cannot usually be executed directly by the processor. They must first be translated into lower-level instructions using a compiler or an interpreter.

High-level-language process:
Human-readable program → Compiler or interpreter → Machine instructions → Processor
R

Readable

The instructions are easier for humans to read and understand.

W

Easier to Write

One high-level instruction may represent several low-level operations.

D

Easier to Debug

Programmers can locate and correct errors more easily.

P

More Portable

Many high-level programs can run on different operating systems with few or no changes.

1.2.5 Is C a Low-Level or High-Level Language?

C is formally classified as a high-level programming language. However, it provides features such as pointers, direct memory access, and efficient hardware interaction.

Because C combines readable programming structures with low-level hardware control, it is sometimes informally called a middle-level language.

Important clarification: The true low-level languages are machine language and assembly language. C is a high-level language with several low-level capabilities.

1.2.6 Where Does Python Belong?

Python is a high-level programming language. It hides most of the complicated details of processor instructions, memory addresses, and hardware operations.

This allows Python programmers to concentrate on the problem they want to solve instead of managing every hardware detail.

Python is considered higher-level than C because Python handles many tasks automatically, including memory management and several low-level operations.

Written using Binary digits Mnemonic instructions Human-readable words and symbols

In one sentence:
Machine language is easiest for the processor, assembly language is a more readable form of low-level instructions, and high-level languages are designed to make programming easier for humans.

3. Python Versions, Implementations, and Libraries

Stage I · Programming and Setup Know Your Python

You Installed Python—but Which Python?

In the previous lesson, we installed Python. You may now be wondering: Why does my computer show a number such as Python 3.14.8? What is CPython? Why do people talk about NumPy, pandas, PyTorch, or Django?

These names belong to three different ideas: versions, implementations, and libraries. They sound technical, but the difference is simple.

Version

A version tells us which edition or release of Python we are using—for example, Python 3.14.8.

Implementation

An implementation is the actual software engine that reads and runs Python instructions.

Library

A library is a collection of ready-made tools that helps us perform useful tasks without building everything ourselves.

Think of Python as a Car

The version is the model year. The implementation is the engine under the hood. The libraries are additional tools and features—such as navigation, sensors, or a music system.

They belong to the same car, but they do different jobs.

What Is a Python Version?

Python continues to improve. Developers fix problems, improve performance, add features, and strengthen security. Each officially released form of Python receives a version number.

Is the newest version always the best choice?

For a beginner, a current stable Python 3 release is normally a good choice. In research or professional projects, however, you may use a slightly older supported version because a required library has not yet been updated for the newest release.

What Is a Python Implementation?

Python is a language with rules. Those rules describe how Python code should behave. But we still need a real program that reads those instructions and makes the computer perform them.

That program is called a Python implementation. Different implementations can follow the Python language while being designed for different computers or purposes.

What Is a Python Library?

Imagine that you want to draw a graph. You could spend months writing everything required to create axes, colors, labels, lines, and image files. Or you could use a library whose developers have already built those tools.

A Python library is reusable code written to solve common problems. Libraries are one of the biggest reasons Python is so useful in science, research, artificial intelligence, automation, and web development.

Standard Library

These tools are included when Python is installed. You do not normally need to download them separately.

Examples: math datetime pathlib json csv

Third-Party Libraries

These libraries are created outside Python's standard library. We install them when a project requires them.

Examples: NumPy pandas Matplotlib PyTorch

Questions That May Come to Your Mind

Is a Python version the same as an implementation?
No. A version describes a release of the language, such as Python 3.14. An implementation is the program that runs Python, such as CPython or PyPy.
Is Anaconda another Python implementation?
No. Anaconda is a Python distribution. It bundles Python with package-management tools and many libraries commonly used in science and data analysis.
Is Jupyter Notebook a Python implementation?
No. Jupyter is an interactive environment in which you can write and run Python. It normally uses a Python implementation such as CPython underneath.
Will every library work with every Python version?
Not always. A library may need time to support a newly released Python version. This is why researchers sometimes use a slightly older but well-supported Python version.
Is PyPy always faster than CPython?
No. PyPy can make some long-running Python programs faster through just-in-time compilation, but performance depends on the program. Compatibility with some extension libraries can also differ.
Can normal Python code run on MicroPython?
Some code can, but not everything. MicroPython is designed for small devices with limited memory, so it provides a smaller standard library and has some differences from desktop Python.
How many libraries should I learn?
Begin with Python fundamentals. Then learn only the libraries required for your work. Knowing five relevant libraries well is more useful than memorizing the names of one hundred.

Questions That May Come to Your Mind

Do these tools use different Python languages?
No. The Python language remains the same. These tools provide different ways to write, organize, run, and examine Python instructions.
Is VS Code itself a Python interpreter?
No. VS Code is an editor. You must install Python separately and then select that interpreter inside VS Code.
Is Jupyter an IDE?
Jupyter is more accurately described as an interactive notebook environment. It combines executable cells, formatted text, mathematical equations, figures, and results in one document.
Which one is easiest for a complete beginner?
IDLE is the simplest because it is small and normally included with Python. VS Code requires a little more setup but is more useful as your projects grow.
Which one is best for researchers?
Jupyter is excellent for exploration, figures, equations, and data analysis. VS Code is useful for larger reusable programs. Many researchers use both.
Should I install all four?
No. Begin with one. For this course, VS Code is a good main choice. You can add Jupyter later when you begin working with data and scientific experiments.
Can VS Code open Jupyter notebooks?
Yes. With the appropriate Python and Jupyter extensions, VS Code can open and run .ipynb notebook files.
